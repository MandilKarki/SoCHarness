1. PILOT ARCHITECTURE
Fly HTTPS edge -> one non-root Relay container -> bounded local SDK subprocesses.
One Fly volume stores SQLite, SDK session directories and text workspaces at /data.
Use ONLY benchmark/sanitized records that you are authorized to host and send to model providers.
Pilot login uses a high-entropy operator token, not an API key. This is single-operator
access, NOT distinct users, tenant isolation, MFA, enterprise SSO, or role separation.
Rotate the token via secrets and restart to revoke all browser sessions. Sessions are
memory-only, expire after eight hours, and restart invalidates them. Sign-out revokes one.
API writes require the exact HTTPS Origin; cookies are Secure, HttpOnly, SameSite=Strict.
Global sign-in throttle: ten attempts/minute. Put additional abuse controls at the edge.
The HTTP listener must remain behind the TLS proxy; never expose port 8787 directly.

5. BACKUP / RESTORE
python services/backup.py PATH_TO_NEW_BACKUP.sqlite3
Uses SQLite online backup and integrity_check, including committed WAL data.
Also back up native-workspaces, claude-sandbox, claude-home, adapter-sessions and SDK-owned session
storage as applicable. A database backup alone does not preserve native SDK file state.
The utility does not schedule/upload backups or encrypt them. Protect backup files.
Restore onto an empty isolated volume, run integrity_check, verify cohort/session counts,
and test retrieval before switching traffic. Fly volumes are local and not automatically
replicated across Machines. Volume snapshots do not substitute for tested off-site backup.
